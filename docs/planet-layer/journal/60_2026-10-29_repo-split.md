### Repository split (29 Oct): the planet chain moves to Planetary_Diffusion, history kept, identity proven; Infinite_Diffusion keeps the original generator

The plan is in the Claude Doc "Planet generator: repository migration plan" (29 Oct; decisions recorded there: name
`Planetary_Diffusion`, public, the pre-split tag is the archive of the learned-layout era, no `archive` branch).
No model change: PARAMS, defaults and code paths are as they were after the forty-first pass.

**Phase 0 (old repository).** `.gitignore` had excluded `scripts/`, `tests/`, `docs/` and `*.cmd` since September, so
those had never been committed. Commit `baf9fc7` added them: 271 files, all text, the largest 360 KB, with no secrets.
It also added the uncommitted `plates.py` (B-d2, default off) and the new `tools/`. It was pushed, and then tagged
`pre-split-2026-10-29` and pushed. The old remote is `github.com/finnnosam/Planetary-Infinite-Diffusion`.

**Phase A (new repository** `github.com/finnnosam/Planetary_Diffusion`, public, at `E:\projects\Planetary_Diffusion`):
- **Import with history.** A temporary clone of the old repo at the tag was filtered with `git filter-repo` to the
  paths in `migration/split-paths.txt` (103 entries). The list was generated from each file's imports and corrected
  by hand: seven files import live modules but belong to the learned era, and two more were pulled in because they
  import chain scripts. That gave:
  - `planet_layer/`, `toy_meso/`, and 5 + 6 `planet_training` modules (see below);
  - 47 scripts, 13 test files, 5 tool entries;
  - the planet docs and 22 sweep `.cmd`s.

  The result was merged (unrelated histories) into the repo's first commit. `git log` of `planet_layer/` reaches back
  to September.
- **Environment.** A new `.venv` with the old venv's exact versions: Python 3.12.14, numpy 2.5.3, numba 0.68.0,
  ducc0 0.41.0, torch 2.14.0+cu130, and the rest from `pip freeze`. Two additions: h5py and git-filter-repo. The old
  repo is installed in editable mode with `--no-deps`, for `planet_diffusion.cube` and `.procedural`. This is the
  only remaining link, cut in phase B.
- **Data and outputs** were renamed across on the same drive, so nothing was copied:
  - `data/`, whole;
  - from `outputs/`: planet-calibration, planet-landscape, planet-landscape-timing, planet-meso-check, planet-plates,
    planet-reference, erosion-law-check, meso, meso-plains-diagnosis, toy_meso, tectonic-prototype, claude-sync.

  The generator reads neither folder. The learned era's outputs stay in the old repo.
- **Three problems on the first test run** (108 passed, 2 failed, 49 errors), all from setup, none from the model:
  1. Pytest's system temp folder (`%TEMP%\pytest-of-<user>`) is not readable on this machine. The meso tests
     use `tmp_path`; the planet-layer tests never did. Now `addopts = --basetemp=outputs/pytest-tmp`.
  2. `terrain_structure` imports `adaptation`, `data` and `train` by relative import, and those pull in `layout`,
     `progress` and `run_lock`. The import scan had not followed relative imports. All six were copied in unchanged.
  3. Git on Windows checked the files out with CRLF, while the originals are LF. The meso stage hashes its own source
     files (`random_fingerprint`), so one test failed. `.gitattributes` now sets `* text=auto eol=lf` and
     `*.cmd eol=crlf`, and the working tree was converted back. All 194 moved files are byte-identical to their
     originals.
- **Check:** 159 tests pass. The identity run (`sweep_plates --seeds 1001`, working baseline, today's arc settings) equals
  `sweep-20261028-200644/trench_polarity-node_trench_flux-band_arc_H_ocean_m-300_arc_accretion-False/seed1001` on
  62 snapshots × 18 fields. `stats.json` differs only in `seconds`. Pushed (`cd667b8`).
