# 155 — 27 Nov 2026 — Cube lookup and mantle flow speed

This implements the first pass of the sweep speed guide. Cube lookups share one 16,384-bin table per resolution.
Each bin covers a range of coordinate ratios. If rounding can change anywhere in the widened range, the lookup
uses the original `atan2` formula for that coordinate. The face selection still uses the largest absolute component
and breaks ties in axis order.

The mantle flow computes transform coordinates and tangent vectors once for the world grid. It uses them for
topography and both velocity paths. The unscaled velocity starts at zero and is synthesized on first access after
each coefficient update. The measured-power rift traction path synthesizes the velocity from its scaled coefficients.

## Component timings

At grid 217 and two threads, all 19,494,984 chart entries matched across 69 saved rotations at −200, −100 and 0 Myr.
The final epoch had 41 plates. Times are medians in milliseconds on the saved states.

| Operation | Before at −200 / −100 / 0 Myr | After at −200 / −100 / 0 Myr |
|---|---|---|
| Full-grid cube lookup per plate rotation | 2.94 / 2.92 / 2.94 | 1.21 / 1.20 / 1.21 |
| Mantle velocity gradient | 30.95 / 30.85 / 38.38 | 15.82 / 15.80 / 25.48 |
| Mantle scalar synthesis | 14.38 / 14.33 / 21.30 | 8.79 / 8.78 / 15.63 |

The default path saves one cached gradient whenever the unscaled field goes unread. That saves 16–25 ms on the
sampled states after taking geometry reuse into account. One-time chart table and mantle geometry construction
took 0.34 ms and 14.93 ms, respectively. The mantle arrays occupy 18.08 MB per worker. The separate cold crust
flow table builds took 0.25 s for sheet flow and 4.71 s for channel flow.

Seed 1001 took 2.11 s per warm step and state record in the baseline, 2.05 s with just the cube table, 2.05 s with
just the mantle changes, and 1.99 s with both. Each timing covers 15 warm steps at grid 217 and two threads.

## Eight-worker timings

Each of eight jobs at grid 217 ran 25 warm steps at two threads, using the same seeds and workload on each side.
Wall time includes worker startup. The second trial reversed the order of the baseline and optimized runs.

| Case | Baseline | Both changes | Wall time saved |
|---|---:|---:|---:|
| First trial | 122.93 s | 117.32 s | 4.6% |
| Reverse order | 120.70 s | 118.11 s | 2.1% |

The reverse-order trial measured the Python workers directly. Their combined peak working set went from
6,261 to 6,335 MiB, and the highest individual worker peak went from 907 to 917 MiB. Both changes are enabled
based on exact trajectory checks and faster wall time in both trials.
