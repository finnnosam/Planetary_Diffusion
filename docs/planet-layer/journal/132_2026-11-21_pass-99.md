#### 1. What was built

`flow_power` (PARAMS, default 'flow'; acts only with `dyn_rule` 'slabs'):

- **'flow'**: D as built (the flow's own amplitude). Unchanged.
- **'measured'**: after the flow is solved, every coefficient of degree l is multiplied by √(P_measured(l) / P_flow(l)),
  with P_measured the same table `dyn_rule` 'measured' reads (`mantle.measured_power_air_m2`: Valentine & Davies 2020,
  l 1–30, air-loaded). So the field's power per degree is Earth's exactly and its shape within each degree (where the
  highs and lows lie) is the planet's slab record. Degree 31 and degree 0 are zero (beyond the measurement). A degree
  the record does not yet load is zero. The surface velocity stays the flow's own (it acts only through
  `basal_traction`, off). Water loading under the sea, hotspot swells and the record are D's. No number is added or
  fitted: the amplitude is the measurement, the pattern is the mechanism.
- **The start** (second build, §3): the record starts empty, so the start's mantle is `dyn_rule` 'measured''s own field
  (same stream, `[seed, 8]`): the arm's start is identical to the control's (tested; and on seed 1024 every start field
  is equal). It hands over to the placed field at constant variance (cos / sin of a smooth angle, as the measured field's
  own knot blend) over one knot interval, `dt_knot_myr` 40 Myr, the measured field's own decorrelation step. No new
  number. From −210 Myr on the field is the placed one alone.
- Snapshots (contract changed first, `docs/contracts/plate-snapshots.md`): with 'measured', `flow_topography_alm_m` is
  the rescaled field and `flow_power_raw_m2` (32 numbers) holds the flow's own air-loaded power per degree.
- `crust_review.PREDATING` gains `flow_power` 'flow'. `tests/test_flow_power.py` (5 tests, in `run_sweep.PLANET_TESTS`):
  Earth's power per degree to 1e-9 and the flow's shape within each degree, lows over the record's mass, an empty
  record gives no field, a bad value raises, the default is 'flow', a slabs run saves the raw power, the start equals
  the control's and the handover ends at one knot interval.
- **Identity** of the default path (HEAD `442c943` against the edit, bare PARAMS, n = 48, seed 1007, threads 1, 70 steps,

#### 3. The full-length cloud pre-check, first build: V5 failed at the start

Seed 1024 (unused), control and B, n = 217, 250 Myr, threads 1, saves every 5 Myr over the last 40.

The first build (no start field) read: continents (crust ≥ 30 km) under the datum at 0 Myr 0.138 against the control's
0.317 (Earth 0.112), p10–p90 on the datum −47 / 149 / 398 / 689 / 1,151 m (control −568 / −65 / 206 / 622 / 1,270);
drowned band 3.2% (5.8%); land 0.290 (0.268); gates −103 / +31 m; detached 0.0028. **But the highest node in the
snapshots was 9,456 m, at the start** (−250 Myr; control 5,434 there). V5 would fail.

Cause: with `dyn_rule` 'slabs' the start has no field (the record is empty), so `start_cover` 'accommodation''s bare
level is the Airy line plus C alone, nearly a function of the crust. The regression that gives the cover Earth's
correlations with the crust and with the bare level then has large opposite weights (b = (s − r₁₂ s′)/(1 − r₁₂²) with
r₁₂ near 1), and Earth's thickest cover (9 km bulk, the top of the measured distribution) landed on thick crust: 63
nodes above 5 km at −250 Myr (control 4), one at 9.5 km on 48.8 km of crust under 7.6 km of solid cover. Gone by −240
Myr. This is a start defect the arm exposed, not the placement: on Earth the mantle under the supercontinent had a
field, which the empty record cannot give. Fixed in the build (§1, the start), before any sweep: the arm starts from the
control's own field and hands over in one knot interval, so its start is the control's. The first build's runs are kept
as `precheck-p99-field/placed-v1` in the cloud (not on the device). The start cover's fragility under a nearly
collinear bare level is a watch-point (STATE §6).
